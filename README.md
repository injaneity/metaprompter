# metaprompter

Lightweight specs-first metaprompting framework for agentic coding workflows.

## Zero-Setup Defaults

- If `.metaprompter/config.yaml` is missing, runtime defaults are used automatically.
- `github.repo` is optional and auto-detected from `git remote origin` when empty.
- Codex/OpenCode/Claude adapter commands work out of the box from built-in defaults.
- If adapter scripts are missing, `/execute` auto-generates them.
- If `prompts/execute/worker.md` is missing, `/execute` uses the built-in worker template.

## Commands

- `metaprompter interview [--dry-run] [--config PATH] [--framework NAME]`
  - Run skill-style interview via selected agent framework (context-driven, not hardcoded questionnaire), aligned to OpenCode interview-mode guiding principles, then sync task snapshot.
- `metaprompter execute [--dry-run] [--config PATH] [--issue N] [--max-issues N]`
  - Rebuild task snapshot, reset session log, and execute issues (serial primary + optional subissue fan-out).
- `metaprompter prompts scaffold`
  - Optionally scaffold fixed prompt templates, command definitions, and default config for customization.
- `metaprompter adapters generate [--config PATH]`
  - Generate thin adapter scripts from command definitions (optional; auto-generated by `/execute` when needed).

## Homebrew

You can install via Homebrew today (head build):

```bash
brew install --HEAD https://raw.githubusercontent.com/injaneity/metaprompter/main/Formula/metaprompter.rb
```

For team/internal usage with upgrades, use a tap; see `docs/brew.md`.

## Key Artifacts

- `docs/spec/*.md`: generated canonical spec pack.
- `docs/modules/*.md`: generated for medium/high complexity modules.
- `tasks.md`: rebuilt snapshot from GitHub issues in chronological order.
- `log.md`: session log with strict line format:
  - `<timestamp> [<issue number>] <action>`

## Minimal Requirements

1. Run inside a git repo connected to GitHub (`origin` remote).
2. Authenticate `gh` CLI.
3. Have the selected agent CLI installed (`codex`, `opencode`, or `claude`).

## Framework Commands

- `/interview` uses interactive framework commands:
  - `codex "$(cat "$PROMPT_FILE")"`
  - `claude "$(cat "$PROMPT_FILE")"`
  - `opencode --prompt "$(cat "$PROMPT_FILE")"`
- `/execute` uses non-interactive commands:
  - `codex exec - < "{{prompt_file}}"`
  - `claude -p "$(cat "{{prompt_file}}")"`
  - `opencode run "$(cat "{{prompt_file}}")"`

## Execution Model

- Source of truth for task state is GitHub issues.
- `/execute` rebuilds `tasks.md` each session.
- `/execute` resets `log.md` at session start.
- One retry per issue, then mark blocked + create follow-up issue.
- Branch naming convention: `issue-<num>-<slug>`.
- One issue maps to one branch and one pull request.
